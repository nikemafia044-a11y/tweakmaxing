# TweakMaxing v2 (2.0.0): design

Fonte: o pedido "TweakMaxing v2" do usuário e as imagens em `docs/design/` (disposição, espaçamento e textos). Quando a imagem e a
tabela de tokens divergem, vale a tabela. Não se consulta nenhum outro programa instalado: o código é escrito do zero,
com base na documentação pública do Windows.

Decisões do usuário (2026-09-24):
- As abas atuais Configurar (Recursos, Correções, Painéis, DNS) e Atualizações viram o item **Sistema** do menu, com sub-abas.
- **Sem Discord Rich Presence.**
- **Idioma:** pt-BR e **inglês**, com escolha na primeira abertura (tela inicial) e seletor na barra de título. A interface
  inteira e os textos do catálogo (ajustes e apps) têm versão em inglês.
- Framework mantido: WPF + WebView2 com HTML/CSS/JS vanilla. A ponte JSON, os jobs, a sessão, o ponto de restauração,
  o state.json, o Desfazer, o modo headless e o `irm | iex` continuam como estão.

`--bg-elevated #1D2024`, `--border #26292E`, `--border-strong #33373D`, `--text-primary #ECEDEE`, `--text-body #D5D8DC`,
`--text-secondary #A0A6AD`, `--text-muted #8E949B`, `--accent #2DD4BF`, `--accent-text #5EEAD4`, `--accent-tint #17302C`,
`--on-accent #0B0C0E`, `--risk-low-bg #13261F`, `--risk-low #6EE7B7`, `--risk-medium-bg #2A2210`, `--risk-medium #F5C66A`,
`--risk-high-bg #2E1719`, `--risk-high #FCA5AB`, `--danger #F0616A`.
Os tokens antigos (`--bg`, `--panel`, `--panel-2`, `--elevated`, `--linha`, `--fg`, `--muted`, `--accent-fg`, `--active*`,
`--ok`, `--warn`, `--laranja`) ficam como **apelidos** dos novos, para não quebrar CSS que não for reescrito.
O app só tem tema escuro: o tema claro sai.
Raios: `--r-lg 16px` (cards grandes), `--r-md 14px` (cards), `--r-sm 10px` (botões). Área de clique mínima de 44 px.

## 2. Janela

- **Barra de título própria:** a janela WPF passa a `WindowStyle=None` com borda redimensionável
  (`WindowChrome`, com `CaptionHeight=0` e `ResizeBorderThickness=6`). A barra é HTML (`#titlebar`, 40 px) e tem uma área de
  arrasto. O arrasto usa CSS `app-region: drag` com
  `CoreWebView2Settings.IsNonClientRegionSupportEnabled = $true`, com fallback na ação `window.drag` (`DragMove`).
  Ações da ponte: `window.minimize`, `window.maximizeToggle`, `window.close`, `window.drag` e `window.state` (devolve
  `{maximized}`). Duplo clique na área de arrasto maximiza ou restaura.
- **Menu lateral** `#sidebar` de 248 px (72 px recolhido; o estado fica salvo nas configurações):
  - Logo: quadrado `--accent` com o símbolo, nome e "Otimizador para jogos".
  - Itens `button.aba[data-tab]` com os ids `painel`, `otimizacoes`, `limpeza`, `restauracao`, `aplicativos`, `microwin`,
    `sistema` e `configuracoes`.
  - Item ativo com fundo `--accent-tint` e texto `--accent-text`.
  - Rodapé: card "Proteção ativa", "Versão 2.0.0", link "Novidades" (release notes no GitHub), ícone do GitHub e botão
    de recolher.
- **Barra de status** (`footer#status`, com os ids `#st-*` atuais) continua embaixo do conteúdo.
- **Seções:** `section#tab-<id>`. As atuais mudam de id assim: `#tab-ajustes` vira `#tab-otimizacoes` e `#tab-instalar`
  vira `#tab-aplicativos`. `#tab-configurar` e `#tab-atualizacoes` passam a viver dentro de `#tab-sistema` como
  sub-abas (os ids internos são preservados).
  Os módulos JS se registram em `window.tmxTabs[<id>]`, como hoje. O antigo `tmxTabs.ajustes` passa a se chamar
  `otimizacoes`, e `instalar` passa a se chamar `aplicativos`.

## 3. Idioma (i18n)

- `src/web/i18n.js` define `tmx.i18n`. Cada tela registra as próprias strings no próprio arquivo JS com `tmx.i18n.add('pt-BR', {...})` e `tmx.i18n.add('en', {...})` (chaves com prefixo da tela: `painel.*`, `otim.*`, ...); a casca registra as dela (`shell.*`). Assim tarefas paralelas não disputam um arquivo de traduções.
  `app.js` expõe `tmx.i18n.t(chave, vars)`, `tmx.i18n.lang` e `tmx.i18n.set(lang)`:
  - aplica `data-i18n`, `data-i18n-title` e `data-i18n-placeholder`;
  - dispara o evento `tmx:lang` (as telas redesenham);
  - salva o idioma em `settings.set { language }`.
- **Primeira abertura** (sem `language` nas configurações): uma tela inicial com dois botões grandes (Português (Brasil) e
  English). O seletor da barra de título (globo + bandeira) troca a qualquer momento.
- **Catálogo:** campos de texto localizados. Cada tweak tem `nome`, `oQueFaz`, `beneficio` e `atencao` (em pt-BR) e
  `i18n.en.{nome,oQueFaz,beneficio,atencao}`. Cada app tem `descricao` e `i18n.en.descricao`. O front escolhe pelo idioma,
  caindo em pt-BR quando falta tradução. Mensagens de erro do back-end continuam em pt-BR (limitação documentada).

## 4. Configurações persistentes

- Arquivo `<home>\settings.json`. Ações `settings.get` e `settings.set {chave: valor}`, só para uma lista permitida de
  chaves: `language`, `displayName`, `sidebarCollapsed`, `appliedMode`, `appliedModeAt`, `lastCleanup` e
  `lastCleanupFreed`. Chave fora da lista é recusada.
- Nome de exibição: se `displayName` estiver vazio, vale `$env:USERNAME`. O botão "Usar o nome do Windows" usa o nome
  completo do usuário (`Win32_UserAccount.FullName` ou `whoami /fqdn`, com fallback em `$env:USERNAME`).

## 5. Painel

- Ação `system.info` (job assíncrono) devolve:
  - `cpu {modelo, nucleos}`;
  - `gpu {modelo, vramGB, fabricante}`: a VRAM vem de `HardwareInformation.qwMemorySize` na chave da classe de vídeo
    `{4d36e968-e325-11ce-bfc1-08002be10318}\000N`, com fallback em `AdapterRAM`;
  - `ram {totalGB, tipo: DDR3|DDR4|DDR5|?, velocidadeNominal, velocidadeConfigurada}` (`SMBIOSMemoryType` 24=DDR3,
    26=DDR4, 34=DDR5);
  - `disco {tamanhoGB, tipo: NVMe|SSD|HDD, modelo}`, vindo do disco que tem a partição C:;
  - `os {edicao, displayVersion, build}`;
  - `chassi: desktop|notebook`, pelo perfil do Engine;
  - `hagsSuportado`, `hagsLigado`;
  - `recomendacoes[]`, no máximo 3, cada uma com `{tipo: 'bios'|'app', titulo, texto, guia?}`, geradas por regra a partir
    do hardware. Os casos cobertos: memória abaixo da velocidade nominal (XMP/DOCP/EXPO, com guia passo a passo), HAGS
    suportado e desligado, plano de energia no desktop (seguro) e plano no notebook (não será aplicado). As
    recomendações são localizadas: o back-end devolve chaves de i18n, não texto.
- O status de otimização conta os itens de modo com estado "ativo" no catálogo, contra os disponíveis. O modo atual vem de
  `appliedMode`. O último ponto de restauração vem de `restore.list`.

## 6. Otimizações: modos

- **Catálogo:** todo tweak ganha:
  - `modo`: `leve`, `moderado`, `avancado`, `ultimate` ou `extras`;
  - `categoriasV2[]`, com os filtros `geral`, `aparencia`, `desempenho`, `privacidade`, `jogos`, `rede` e `gpu`;
  - os textos `oQueFaz`, `beneficio` e `atencao` (a atenção pode ser "Nenhuma").
  Regras:
  - FOLCLORE e irreversíveis **nunca** entram num modo e ficam em `extras`;
  - um tweak informativo ou de auditoria (`controle: info`) fica em `extras`;
  - "Plano de desempenho máximo" tem a condição `chassi == desktop` e não é aplicado em notebook;
  - `risco: alto` só no `ultimate`, sempre com confirmação separada (`requerConsentimentoExtra`).
- Os 29 ajustes do pedido são mapeados em `docs/v2/01-mapa-de-funcoes.md`: 20 já existem (mantêm o código e ganham os
  textos novos) e 9 são novos (seção 7). O restante do catálogo é classificado pelas mesmas regras.
- **Seleção por modo:** a ação `mode.select {mode}` equivale a um preset cumulativo (leve ⊂ moderado ⊂ avançado ⊂ ultimate)
  e usa a seleção do plano atual (`plan.setSelection`). A prévia e a aplicação usam o fluxo atual: `plan.preview`, depois
  `plan.apply` com a sessão aberta e o ponto de restauração bloqueante.
- Os ajustes acima do modo aparecem esmaecidos com "Entra no modo X". Dentro do modo, cada item pode ser desligado.
- Ao terminar uma aplicação bem-sucedida, o front grava `appliedMode` e `appliedModeAt`.
- Os presets antigos `desktop`, `notebook` e `minimo` continuam existindo para o headless (`-Preset`); `leve`, `moderado`,
  `avancado` e `ultimate` passam a valer também como `-Preset`.

## 7. Ajustes novos

Cada um ganha trio `Set-/Undo-/Test-Tmx<X>` (ou ações declarativas no catálogo), backup do valor anterior e Desfazer:

| Id | Ajuste | Modo | Mecanismo |
|---|---|---|---|
| INT-024 | Remover atraso dos menus | leve | `HKCU\Control Panel\Desktop\MenuShowDelay` = `0` |
| INT-025 | Desativar dicas da tela de bloqueio | leve | `ContentDeliveryManager`: `RotatingLockScreenOverlayEnabled`=0, `SubscribedContent-338387Enabled`=0 |
| PRI-009 | Desativar Wi-Fi Sense | leve | `HKLM\SOFTWARE\Microsoft\WcmSvc\wifinetworkmanager\config\AutoConnectAllowedOEM`=0 (efeito só em builds antigas; dito no texto) |
| JOG-048 | Otimização para jogos em janela | moderado | `HKCU\...\DirectX\UserGpuPreferences\DirectXUserGlobalSettings` com `SwapEffectUpgradeEnable=1;` preservando as outras chaves da string |
| JOG-049 | Otimizar painel da GPU | moderado | detecta o fabricante (NVIDIA/AMD/Intel, pelo `Win32_VideoController`) e mostra um guia manual passo a passo, em texto, para o painel do fabricante (modo de energia de desempenho máximo, sincronia vertical conforme o jogo, baixa latência). Não altera nada sozinho: o estado é só informativo (`controle: info`, fica em `extras` com link para o guia) |
| SIS-014 | PowerShell 7 como padrão | extras | `winget install Microsoft.PowerShell` se faltar; perfil padrão do Windows Terminal (`settings.json`, `defaultProfile`) com backup do arquivo |
| APM-006 | Remover bloatware (escolher o que manter) | avançado | lista dos appx do catálogo `appx.json` instalados; o usuário marca o que manter; remove o resto; volta pela Store (`storeId`) |
| APM-007 | Remover apps de jogos da Microsoft | avançado | remove os appx de jogos pré-instalados; **pergunta** se usa Game Pass e, se sim, mantém Xbox App e Game Bar |
| SEC-001 | Proteção em tempo real do Defender | ultimate | primeiro oferece a alternativa segura (exclusão de pastas de jogos, que reaproveita DefenderExclusion); se a pessoa insistir, abre `windowsdefender://threatsettings` e mostra o passo manual (a Proteção contra Adulteração impede fazer por script); o estado é só lido |

"Serviços pouco usados como manual" (SIS-001) continua FOLCLORE e, por isso, **não entra no Avançado**: fica em `extras`
e o texto explica o motivo. Isso contradiz a tabela do pedido, e está documentado em `02-relatorio.md`.

## 8. Limpeza

- Ações `cleanup.scan` (job; devolve `{itens:[{id, bytes, arquivos}]}`) e `cleanup.run {ids}` (job; devolve
  `{liberado, porItem}`).
- Itens:
  - `temp-usuario` (`%TEMP%`);
  - `temp-sistema` (`%WINDIR%\Temp`);
  - `wu-cache` (`SoftwareDistribution\Download`, parando e religando o `wuauserv`);
  - `miniaturas` (`thumbcache_*.db` do Explorer);
  - `lixeira` (`Clear-RecycleBin`), marcado **Perigoso**;
  - `prefetch` (`%WINDIR%\Prefetch`), marcado **Não recomendado**.
- Arquivo em uso é pulado e contado. `lastCleanup` e `lastCleanupFreed` são salvos.
- No modo de teste, tudo acontece numa raiz falsa dentro da home de teste.

## 9. Restauração

- Ações `restore.list`, `restore.create {nome?}`, `restore.delete {sequencia}` e `restore.restore {sequencia, confirmado}`.
  - `restore.list` usa `Get-ComputerRestorePoint` e devolve nome, data e sequência.
  - `restore.create` usa `Checkpoint-Computer`. O limite de 24 h é contornado com
    `SystemRestorePointCreationFrequency=0`, e o valor original é restaurado num `finally`. O nome padrão é
    "TweakMaxing AAAA-MM-DD HH:MM".
  - `restore.delete` chama `SRRemoveRestorePoint` (srclient.dll, via Add-Type).
  - `restore.restore` usa `SystemRestore.Restore` via WMI, sem reinício automático. A tela confirma e avisa para
    reiniciar.
- No modo de teste, todas as quatro são simuladas.

## 10. Aplicativos

- O catálogo atual (236 apps) continua, com as categorias mapeadas para Navegadores, Comunicação, Jogos,
  Desenvolvimento, Multimídia e Utilitários.
- O card mostra: caixa de seleção, logo de 44 px, nome, descrição (no idioma), ID do winget em mono, link oficial e o selo
  "Instalado".
- O cache de ícones passa a 88×88 (2x de 44).
- As falhas de imagem ficam com as iniciais (`onerror` volta às iniciais): **nunca aparece ícone quebrado**.
- Ações novas: `apps.export` (devolve `{apps:[ids]}`; o front salva o arquivo pelo diálogo nativo `shell.saveFile`) e
  `apps.import` (lê o JSON pelo `shell.openFile`, valida os ids contra o catálogo e marca a seleção).
- Aviso com link para Otimizações › Remover bloatware.

## 11. MicroWin

- Opções novas no build:
  - `removerOneDrive`, `removerEdge`: appx e pastas offline;
  - `desativarTelemetria`: `reg load` do SOFTWARE e do SYSTEM offline, políticas de telemetria, `reg unload`;
  - `contaLocal`: autounattend, como já existe;
  - `incluirDrivers`: `Export-WindowsDriver -Online` numa pasta de trabalho e depois `Add-WindowsDriver -Recurse`;
  - `removerDefender`: vermelho e desligado por padrão; remove os pacotes do Defender da imagem.
- A ação `microwin.cancel` interrompe o build, desmonta a imagem com `-Discard` e apaga a pasta de trabalho.
- O progresso vem por etapa e o log fica visível.
- O espaço necessário é calculado a partir do tamanho da ISO × 3 + 5 GB.
- Nunca opera no disco em uso: a imagem sempre vai para a pasta de trabalho.
- Os textos seguem a imagem `04-microwin.png`.

## 12. Configurações

Seções:
- **Perfil:** nome de exibição e "Usar o nome do Windows".
- **Aparência:** idioma e menu recolhido.
- **Sistema:** versão e "Verificar atualizações", que chama `app.checkUpdate` na API do GitHub
  `releases/latest` do repositório do arquivo REPO e mostra se há uma versão nova, com link.
- **Privacidade e dados:**
  - limpar o cache do app (ícones e ui antigas);
  - abrir a pasta de logs;
  - excluir backups antigos: as execuções em `runs` com mais de 30 dias, exceto a mais recente, depois de uma
    confirmação que lista quantas são.

  Os caminhos aparecem na tela.

## 13. Testes e verificação

- Pester para cada módulo novo: hardware (com mocks de CIM e registro), limpeza (raiz falsa), restauração (wrappers
  mockados), configurações, ajustes novos (Set/Test/Undo na chave de teste) e modos (acumulação e exclusões).
- GUI com o agent-browser: os scripts `tests/gui/*` são atualizados para as abas novas, e entram testes novos para
  Painel, Limpeza, Restauração, Configurações, idioma e barra de título.
- Palette.Tests com os tokens novos.
- O artefato compilado roda o headless com `-Preset moderado -DryRun`.
- Entregável: `docs/v2/02-relatorio.md`.

## Riscos e limites

- **Seletores dos testes de GUI mudam muito:** os scripts são atualizados junto com cada tela, e a suíte roda completa no fim.
- **O MicroWin com ISO real e VM** depende de uma ISO oficial no disco e de Hyper-V. Se não houver, o build real não é
  executado e isso fica registrado no relatório. A lógica é coberta por testes com wrappers.
- **Restaurar ponto real e excluir ponto real** não são executados nesta máquina durante os testes, só simulados, porque
  restaurar reverteria o sistema.
- **Aplicar os ajustes novos em HKLM de verdade** exige elevação. Os testes usam a chave de teste em HKCU; o
  Aplicar/Desfazer real fica no roteiro manual.
- **As mensagens do back-end** não são traduzidas nesta versão.
